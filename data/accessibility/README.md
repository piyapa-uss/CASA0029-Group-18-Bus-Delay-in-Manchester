# `data/accessibility/` — Data README

This folder holds every dataset that powers the **Accessibility & Bus Network Context** section of the site. Two visualisations consume it: the 3D GMAL map (`#accessibility-map`) and the borough-level heatmap (`#gmal-lad-heatmap`). Both are wired up in [`js/accessibility.js`](../../js/accessibility.js).

## Schemas

### `gmal_2016.json` and `gmal_2026.json`

Compact tuple-encoded payload (kept flat to minimise download size).

```json
{
  "stats": { "count": 129109, "min": 0.0, "max": 158.65, "avg": 6.14 },
  "data":  [
    [lon, lat, overall, level, bus, rail, metro, locallink],
    ...
  ]
}
```

| Index | Field | Notes |
|---|---|---|
| 0 | `lon` | Longitude (WGS84) |
| 1 | `lat` | Latitude (WGS84) |
| 2 | `overall` | Composite GMAL score for the cell |
| 3 | `level` | Discrete GMAL band, 1 (very low) to 8 (excellent) |
| 4 | `bus` | Bus-only sub-score |
| 5 | `rail` | National rail sub-score |
| 6 | `metro` | Metrolink sub-score |
| 7 | `locallink` | Local Link demand-responsive sub-score |

The grid is identical between years (same 129,109 cells), so 2016 and 2026 are directly comparable cell by cell.

### `gm_lad.geojson`

A `FeatureCollection` of the ten Greater Manchester metropolitan boroughs. Each feature has a single property `LADNM` (Bolton, Bury, Manchester, Oldham, Rochdale, Salford, Stockport, Tameside, Trafford, Wigan) and a Polygon geometry in WGS84.

### `gmal_lad_means.csv`

Long-format aggregate produced by the notebook. One row per `(year, LADNM)`.

```csv
year,LADNM,cell_count,overall,bus,rail,metro,locallink
2016,Bolton,13975,5.502,4.118,0.374,0.0,1.01
2016,Bury,9955,5.385,4.186,0.0,0.473,0.726
...
```

| Column | Meaning |
|---|---|
| `year` | `2016` or `2026` |
| `LADNM` | Borough name (matches `gm_lad.geojson`) |
| `cell_count` | Number of GMAL grid cells whose centroid falls inside that LAD |
| `overall`, `bus`, `rail`, `metro`, `locallink` | Mean of each score field over those cells, rounded to 3 d.p. |

## Processing pipeline

The CSV is regenerated by [`gmal_lad_means.ipynb`](gmal_lad_means.ipynb).

```
gmal_2016.json   ──┐
gmal_2026.json   ──┼──►  parse to DataFrame  ──►  GeoDataFrame (Point geometries)
                   │                                           │
gm_lad.geojson  ───┴──►  GeoDataFrame (Polygons) ──────────────┤
                                                               ▼
                            gpd.sjoin(predicate="within")   (point-in-polygon)
                                                               │
                                            groupby("LADNM").mean() per year
                                                               │
                                                               ▼
                                                gmal_lad_means.csv
```

Key methodological choices:

- **Spatial join, not bounding-box.** Each grid point is assigned to the borough whose polygon contains it, so cells near borough edges are attributed correctly.
- **CRS.** All inputs are WGS84 (EPSG:4326). The join is performed in geographic coordinates because the cells and polygons share that CRS.
- **No frequency weighting.** The mean is taken over GMAL grid cells, not over population or service frequency. The result is a "geometric mean accessibility" of the borough's land area, which is the right framing for spatial reach but is not equivalent to "average resident's access".
- **Long format.** One row per `(year, LADNM)` rather than wide year-pairs, so the same CSV can drive both the side-by-side heatmap and the Δ panel without reshaping in the browser.

To reproduce:

```bash
cd data/accessibility
pip install geopandas pandas shapely         # if not already installed
jupyter lab gmal_lad_means.ipynb              # or: jupyter nbconvert --execute --to notebook --inplace gmal_lad_means.ipynb
```

The notebook overwrites `gmal_lad_means.csv` in this folder.

## How the data is used in the visualisation

### 1. The 3D GMAL map

[`renderMacroAccessibilityMap` → `bootGmal3DMap`](../../js/accessibility.js)

- `gmal_2016.json` and `gmal_2026.json` are fetched in parallel on map load.
- The active year's `data` array feeds a deck.gl `ColumnLayer`. Position uses tuple indices `[0, 1]`; elevation is `score / global_max × 2800 m × heightScale`; colour follows the active metric (overall = discrete 8-class GMAL palette via tuple index `3`, others = continuous gradient over the per-metric raw score).
- `gm_lad.geojson` is added as a MapLibre GeoJSON source with a transparent fill and white outline. Hover highlights via `feature-state`. Click computes the polygon's bbox and calls `map.fitBounds(...)`, plus reveals a "Back to Greater Manchester" reset button.
- Tooltips (`deckgl.pickObject` on mousemove) display every per-mode score for the hovered cell, decoded straight from the tuple.

### 2. The borough comparison heatmap

[`renderGmalLadHeatmap` → `parseGmalLadCsv` → `drawGmalLadHeatmap`](../../js/accessibility.js)

- `gmal_lad_means.csv` is fetched once on init and parsed into a nested object `{ LADNM: { '2016': row, '2026': row } }`.
- The main panel is a CSS-grid table with rows sorted by `2016.overall` (descending) and ten columns (five metrics × two years). Cell colour uses a per-metric linear scale from `rgb(22,34,54)` to `rgb(88,166,255)`; numeric labels are formatted as `0.00` below 1 and `0.0` otherwise.
- The Δ panel underneath shows `2026 − 2016` with a diverging palette (red → slate → green) on a per-metric symmetric scale around zero.
